SEARCHING  ( / )

  Type words to narrow the list. Matching is fuzzy and ignores case: the
  letters must appear in order, so "dplearn" finds "Deep Learning". Plain words
  are matched against the key, title, authors, year and tags.

  AND   Separate terms with spaces; every term must match.
          swarm 2021              swarm AND 2021
          author:smith tag:ml     both conditions
  OR    Separate alternatives with | inside one term.
          tag:ml|vision           tagged ml OR vision
          swarm|flocking robot    (swarm OR flocking) AND robot
  NOT   Put ! before a word or a field's value.
          !survey                 nothing that matches "survey"
          tag:!read               not tagged read
          tag:!ml|vision          tagged neither ml nor vision

  There are no parentheses: an OR covers a single term only.

EXACT MATCHES

  'word     contains exactly "word" (no fuzzy matching)
  ^word     starts with "word"
  word$     ends with "word"
  ^word$    is exactly "word"
  "a b"     quotes keep a phrase together:  "multi robot"

FIELDS

  name:value searches only one field:
    author  title  year  doi  type  tag  coll (collection)  key  status
  Any other field in a reference file also works (journal:, publisher:,
  abstract:, ...), as does any table column.

    status:"^To Read$"        exactly that status (quote values with spaces)
    coll:^thesis              in "thesis" or any sub-collection of it
    year:2023|2024|2025       years are text, so list them; there are no ranges
    doi:""                    the field is empty: references without a DOI
    status:""                 references without a reading status

FILTER  ( f )

  A form with one box per field (author, title, year, tag, collection,
  status, type, DOI) plus free text. It edits the same query as /, so
  everything above works inside the boxes, | and ! included. Tab moves
  between boxes, Enter applies, Esc cancels.

  Below the boxes, values the library already has for that field are
  suggested as you type (after the last |, if any). Ctrl-N and Ctrl-P pick
  one, and → puts it in the box.

SORT  ( s )

  Choose key, title, first author, year, reading status or type. Choosing the
  current field again reverses the order. References missing the field always
  go last.

SAVED (CUSTOM) SEARCHES

  1. Search with / or f until the list shows what you want.
  2. Type  :save <name>
  The search appears near the top of the library column, marked ⌕. Select it
  to show its references; a / search then narrows within it (AND). To delete
  it, select it in the library column and press dd.

  Saved searches live in yeda.toml, so you can also write them by hand:

    [searches]
    "To read"          = 'status:"^To Read$"'
    "Thesis, unread"   = 'coll:^thesis status:!^Read$'
    "Vision or ML"     = 'tag:vision|ml'

  The library column also lists every collection (a collection includes its
  sub-collections) and every tag. Selecting one filters the list the same way.

CITATION GRAPH  ( :graph )

  :graph graphs the selected reference, or the marked ones (v, V; V G marks
  the whole list).

  The graph shows the seeds (⊚, or ⊙ when opened while exploring), other
  library papers citing or cited by them (◎), and the 20 papers outside the
  library linked to the most seeds (○). Rows are years, newest at the top.
  Only the selected paper's citations are drawn, the one to the picked paper
  bright. It stays in the right column and follows the reference list.

  The list under it has tabs, switched with Tab and shift-Tab: Seeds, Cites
  → (what the selected paper cites), ← Cited by, ▲ Top cited and ▼ Top
  citing (outside papers cited by or citing the seeds). Rows show the year
  and OpenAlex's citation count; s sorts by either. Cites and Cited by list
  papers in the graph until a paper is opened with Enter. Opening one makes
  it a seed (⊙ if it wasn't one; the starting seeds are ⊚): the graph is
  rebuilt with its citing works, its full reference list and everything
  ranked over all seeds. The next :graph starts over; what was fetched stays
  cached. Exploring never adds to the library; a does. j/k pick a paper,
  Enter opens it, Backspace goes back, a adds it by DOI, o opens its DOI in
  the browser, N shows only the selected paper and its direct links (again
  for all), and Esc (or q anywhere, or :graph close) closes the graph.

  A busy year takes up to four rows, and labels go to the most important
  papers first: the selected one, the picked one, the listed ones, the
  seeds. Papers left without room show just their marker. A graph
  taller than the column scrolls with Ctrl-e/Ctrl-y or the mouse wheel, and
  follows the picked neighbour.

  Data comes from OpenAlex. References are matched by DOI and get an
  `openalex` field. For each seed, its references and its 100 most cited
  citing papers are fetched, then cached, so later graphs are instant. What
  OpenAlex doesn't have is remembered too. :graph! fetches the citing papers
  again and retries what wasn't found. Set the counts in yeda.toml:

    [graph]
    outside = 20
    citing = 100

  An API key is optional. Without one, OpenAlex gives a small daily budget
  shared by everyone on your IP address; a free key (from
  openalex.org/settings/api) has its own, larger one. :secrets sets it
  and keeps it in the system secret store, never in a file. You are also
  asked when the keyless budget runs out, and OPENALEX_API_KEY works too.

CITING  ( :cite [format] )

  Copies the selected or marked references to the clipboard. The format is
  bibtex; ident, one identifier per line (the DOI, else the arXiv ID, the
  ISBN or the URL; a pastes them back in); the name of a citation style
  (ieee, apa, chicago-author-date, vancouver, nature, …), or the path of a
  .csl file, relative to the library or starting with ~/. Without one it
  uses [cite] format from yeda.toml, else bibtex:

    [cite]
    format = "ieee"

FETCHING PDFS  ( :fetch [location] )

  For the selected or marked references without a PDF, :fetch tries, in order:
  an open-access copy (arXiv and others, found through OpenAlex), the
  publisher directly (works on a campus network), and then a browser window
  that opens each paper through the library proxy. In the window you sign in
  when the proxy asks, and click through where it stops (a bot check, a page
  without a PDF link). Its Fetch menu skips a paper or stops; with several
  proxies, it also tries the paper through the next one. Every PDF is
  checked against the paper, then copied or uploaded to the location, as with
  :attach. One from the window that is far longer than the paper (a whole
  issue?) stays in the downloads folder for :attach. The ones that fail are
  listed (:failed) and copied.

    [fulltext]
    location = "papers"                                  # where PDFs go
    proxies = ["https://proxy.example.edu/login?url={url}"]  # in order
    # downloads = "~/yeda-downloads"   the window's own download folder

KEY BINDINGS

  Every key runs a command line, and every action is a command, so :down
  and :annotations work like j and A. Rebind keys in ~/.config/yeda/config.toml:

    [keys.normal]                 # everywhere
    "F" = "cite ieee"             # any command line, with arguments
    "ctrl-g" = "fetch"
    "x" = ""                      # unbinds x
    [keys.graph]                  # in the graph column, before normal
    "J" = "graph-scroll-down"

  Contexts: normal, library, graph, table, annotations. Keys are written as
  typed (j, G, ?, :), with ctrl- and alt- prefixes, or by name: Enter, Esc,
  Tab, Backspace, Space, Up, Down, Left, Right, Home, End, PageUp, PageDown,
  F1.
  Space separates the keys of a sequence: "g g". :keys lists every binding
  in effect and every action.

TABLES  ( :table [name], T )

  Define literature tables in yeda.toml under [tables.<name>], each with its
  columns, an optional describe per column and an optional prompt saying
  what the table is for:

    [tables.lit]
    columns = ["contribution", "method"]
    describe = { method = "Algorithm family, a few words." }
    prompt = "Multi-robot coordination papers."

  :summarize [table] fills the selected reference's row using an LLM profile
  from [llm.<name>]; each paper's rows are kept in notes/<key>.ai.toml.
  Without a table name and with several tables, a list to pick from opens;
  Tab completes the name on the command line.

  :table [name] (or T) shows a table of the selected or marked references
  in the right column; c gives it the whole window. j/k pick a row, h/l a
  column (h from the first goes back to the list). Enter shows the cell in
  full, e edits it in $EDITOR, s sorts by the column (again reverses). /
  shows only rows with every word somewhere in them; f only rows whose cell
  in this column matches (!x: doesn't match x; "": empty). Esc closes the
  cell, then clears search and filters, then closes the table, as does q.
